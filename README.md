# 🎬 TorrServer to Infuse Bridge

Смотрите торренты в **Infuse** (Apple TV, iOS, macOS) без скачивания на диск. Проект показывает раздачи **TorrServer** в Infuse как обычную медиатеку по WebDAV: добавили торрент — через полминуты фильм или сериал появится в Infuse с постером и описанием.

## ✨ Возможности

- **Виртуальная медиатека.** На диск ничего не пишется: дерево `.strm`-файлов строится на лету из текущего состояния TorrServer. Удалили торрент — он сразу пропал из медиатеки, нечего чистить.
- **Папки, которые понимает Infuse.** Имена разбираются через [guessit](https://github.com/guessit-io/guessit): `Movies/Название (Год)/…`, `TV/Сериал/Season 01/Сериал S01E05.strm`. Мультиэпизоды, части фильма (CD1/CD2), кириллица, сэмплы отбрасываются.
- **Пароль не попадает в ссылки.** Потоки открываются по отдельному случайному токену (`/s/<токен>/stream/…`), основной пароль защищает только WebDAV и веб-интерфейс TorrServer. Токен меняется одной командой.
- **HTTPS из коробки.** С доменом шлюз Caddy сам выпускает сертификат Let's Encrypt — шифруются и пароль, и сами потоки.
- **Установка без git.** Скрипт скачивает три файла конфигурации и готовые образы; обновление — смена версии образа. Есть неинтерактивный режим для Ansible или cloud-init.

## ⚙️ Как это работает

| Сервис | Контейнер | Назначение |
|---|---|---|
| **TorrServer** | `torrserver` | Раздачи и HTTP-стриминг (наружу не публикуется) |
| **Bridge** | `infuse-bridge` | Строит виртуальную медиатеку из TorrServer и отдаёт её по WebDAV |
| **Шлюз (Caddy)** | `infuse-gateway` | Basic Auth, потоки по токену, HTTPS |

1. Вы добавляете раздачу в TorrServer.
2. Bridge раз в 30 секунд опрашивает TorrServer и запрашивает список файлов **только для новых** торрентов.
3. Infuse читает медиатеку по WebDAV через шлюз (с паролем).
4. При воспроизведении Infuse открывает ссылку из `.strm`: шлюз проверяет токен и проксирует поток из TorrServer.

## 📋 Требования

- Сервер (VPS или домашний) с Docker и **Docker Compose v2** (команда `docker compose`), а также `curl`.
- Запуск установки от `root` или через `sudo`.
- Для HTTPS — домен, A-запись которого указывает на сервер, и открытые порты 80 и выбранные порты TorrServer/WebDAV.

## 🚀 Установка

```bash
curl -fsSL https://raw.githubusercontent.com/eonyushkin-commits/torrserver-infuse-bridge/main/install.sh | sudo bash
```

Скрипт задаст несколько вопросов, создаст `/opt/torrserver-infuse-bridge` с файлами `.env`, `docker-compose.yml`, `docker-compose.tls.yml`, `Caddyfile`, скачает образы и запустит контейнеры.

### Параметры

| Параметр | По умолчанию | Описание |
|---|---|---|
| Домен | — | С доменом всё работает по HTTPS. Без домена — HTTP по IPv4 |
| IPv4-адрес | определяется автоматически | Нужен только без домена |
| Порт TorrServer | `443` с доменом, иначе случайный `10000–59999` | Веб-интерфейс TorrServer и потоки для Infuse |
| Порт WebDAV | `8443` с доменом, иначе `8080` | К нему подключается Infuse |
| Логин | `admin` | Латиница, цифры, `.`, `_`, `-` |
| Пароль | — | Не короче 8 символов, любые символы, кроме `'` |

### Без вопросов

```bash
curl -fsSL https://raw.githubusercontent.com/eonyushkin-commits/torrserver-infuse-bridge/main/install.sh -o install.sh
sudo BRIDGE_PASSWORD='очень-длинный-пароль' bash install.sh -y --domain media.example.com
```

Все параметры: `bash install.sh --help` (`--ip`, `--ts-port`, `--webdav-port`, `--user`, `--password-file`, `--version`, `--dir`, `--reconfigure`, `--rotate-token`).

## 🍏 Подключение в Infuse

1. Infuse → **Настройки** → **Добавить файлы** → **Другое...**
2. Протокол: **WebDAV**.
3. **Адрес** — домен или IP сервера (без `http://`), **Пользователь** и **Пароль** — из установки.
4. В разделе **Дополнительно** укажите **Порт** — порт WebDAV (по умолчанию `8443` с доменом или `8080` без него). При установке с доменом включите HTTPS.
5. Нажмите **Сохранить** и добавьте папки `Movies` и `TV` в Избранное (⭐).

## 🔄 Обновление и управление

Обновление — повторный запуск установщика: он скачает свежие файлы конфигурации и образы, а параметры возьмёт из `.env`.

```bash
curl -fsSL https://raw.githubusercontent.com/eonyushkin-commits/torrserver-infuse-bridge/main/install.sh | sudo bash
```

Чтобы закрепить версию, укажите релиз: `--version v2.0.0` (образ получит тег `2.0.0`). Без параметра используется `main` и образ `latest`.

Команды выполняются из `/opt/torrserver-infuse-bridge`:

```bash
docker compose ps                  # состояние контейнеров
docker compose logs -f bridge      # журнал медиатеки
docker compose pull && docker compose up -d   # обновить только образы
docker compose down                # остановить
```

| Задача | Как сделать |
|---|---|
| Сменить пароль, порты, домен | `sudo bash install.sh --reconfigure` |
| Выпустить новый токен для потоков | `sudo bash install.sh --rotate-token` — ссылки в медиатеке обновятся сами |
| Поправить `.env` вручную | Отредактировать файл и выполнить `docker compose up -d` |

## 📁 Файлы на сервере

```
/opt/torrserver-infuse-bridge
├── .env                    # параметры (права 600)
├── docker-compose.yml      # контейнеры
├── docker-compose.tls.yml  # порт 80 для Let's Encrypt (подключается при наличии домена)
├── Caddyfile               # шлюз; значения берутся из .env
├── caddy/                  # сертификаты и состояние Caddy
└── ts/                     # данные TorrServer (конфигурация, база, кэш)
```

## 🔐 Безопасность

- TorrServer и Bridge наружу не публикуются: доступ только через шлюз.
- WebDAV и веб-интерфейс TorrServer закрыты Basic Auth. Хэш пароля вычисляется при старте шлюза.
- Ссылки на потоки содержат только токен, но не пароль. Тот, кто узнал ссылку, сможет смотреть потоки, но не получит доступ к TorrServer и медиатеке. При утечке выпустите новый токен (`--rotate-token`).
- **С доменом** весь трафик идёт по HTTPS: и пароль, и токен, и видео.
- **Без домена** трафик идёт открытым текстом. Ограничьте доступ к портам файрволом (ufw, Security Groups) или подключайтесь через VPN (WireGuard).

## 🧳 Переход с версии 1

Версия 1 (nginx-прокси, отдельный WebDAV и парсер, который писал `.strm` в `strm_library`) переносится автоматически: запустите установщик как при обновлении. Он возьмёт логин, пароль, IP и порты из старого `.env`, удалит старые контейнеры, `nginx.conf` и `.htpasswd`. После этого:

- в Infuse пересканируйте источник: фильмы и сериалы теперь лежат в папках `Movies/` и `TV/`;
- каталог `strm_library/` и клон репозитория (`.git`, `README*`, `torr_to_strm.py` и т. п.) в `/opt/torrserver-infuse-bridge` можно удалить.

## 🩺 Troubleshooting

**Медиатека видна, но видео не запускается.** Ссылки в `.strm` ведут на `PUBLIC_URL` из `.env`. Проверьте, что адрес и порт TorrServer доступны с устройства Infuse. После исправления выполните `docker compose up -d` — медиатека обновится сразу.

**Новая раздача не появляется.** Bridge ждёт, пока TorrServer загрузит метаданные торрента, и опрашивает его каждые 30 секунд. Ход видно в `docker compose logs -f bridge`.

**Не выпускается сертификат.** Проверьте A-запись домена и что порт 80 открыт: `docker compose logs gateway`.

**Infuse не подключается к WebDAV.** Проверьте порт WebDAV в файрволе, логин и пароль; с доменом — что в Infuse включён HTTPS.

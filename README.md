# 🎬 TorrServer to Infuse Bridge

Смотрите торренты в **Infuse** (Apple TV, iOS, macOS) без скачивания на диск. Проект связывает **TorrServer** и Infuse через автоматически генерируемые `.strm`-файлы и WebDAV: добавили раздачу в TorrServer — через несколько минут (парсер опрашивает TorrServer раз в 5 минут) фильм появится в медиатеке Infuse с постером и описанием.

## ✨ Возможности

- Полностью контейнерный запуск: на хосте нужны только Docker с Compose и стандартные утилиты (см. «Требования»).
- Установка и обновление одним скриптом `install.sh` — без ручной работы с Git и Compose.
- Готовый образ `parser` из [GHCR](https://ghcr.io/eonyushkin-commits/torrserver-infuse-bridge) — сборка на сервере не требуется.
- Умные имена файлов через [guessit](https://github.com/guessit-io/guessit): Infuse сразу группирует сериалы по сезонам, теги качества (`1080p`, `WEB-DL`) игнорируются, кириллица поддерживается.
- Атомарная запись `.strm` (временный файл + `os.replace()`) — Infuse никогда не увидит пустой или недописанный файл.
- WebDAV и TorrServer защищены HTTP Basic Auth; TorrServer наружу напрямую не публикуется.
- Обновление кода не трогает данные в `./ts` и `./strm_library`.

## ⚙️ Как это работает

Стек из четырёх контейнеров:

| Сервис | Контейнер | Назначение |
|---|---|---|
| **TorrServer** | `torrserver` | Источник раздач и HTTP-стриминга |
| **Nginx-прокси** | `torr-proxy` | Basic Auth перед TorrServer; через него Infuse получает поток |
| **Parser** | `strm-parser` | Опрашивает TorrServer и генерирует `.strm`-файлы |
| **WebDAV** | `webdav-infuse` | Публикует библиотеку `.strm` для Infuse |

Поток данных:

1. Вы добавляете раздачу в TorrServer.
2. Parser обнаруживает её при очередном опросе и создаёт `.strm`-файлы в `./strm_library`.
3. WebDAV публикует библиотеку для Infuse.
4. Infuse индексирует файлы, подтягивает постеры и воспроизводит поток через Nginx-прокси.

## 📋 Требования

- Сервер (VPS или домашний) с `git`, `docker`, `curl`, Docker Compose v2 (или совместимым `docker-compose`), а также `ss` (пакет `iproute2`) и `shuf` (`coreutils`) — их использует `install.sh`.
- Запуск установки от `root` или через `sudo`.

## 🚀 Быстрый старт

```bash
curl -O https://raw.githubusercontent.com/eonyushkin-commits/torrserver-infuse-bridge/main/install.sh
chmod +x install.sh
sudo ./install.sh
```

Скрипт клонирует репозиторий в `/opt/torrserver-infuse-bridge`, интерактивно запросит параметры, создаст `.env`, `.htpasswd` и `nginx.conf`, скачает образ `parser` из GHCR и поднимет контейнеры.

### Параметры установки

| Параметр | По умолчанию | Описание |
|---|---|---|
| `WEBDAV_PORT` | `8080` | Внешний порт WebDAV |
| `WEBDAV_USER` | `admin` | Логин WebDAV и TorrServer-прокси (без пробелов, `:` и `'`) |
| `WEBDAV_PASSWORD` | — | Пароль (общий для WebDAV и прокси); любые символы, кроме `'` |
| `HOST_IP` | — | Внешний IPv4-адрес сервера (домен не поддерживается) |
| `TORR_PORT` | случайный из `10000–60000` | Внешний порт TorrServer (порт прокси) |

> ⚠️ **`HOST_IP` — самый важный параметр.** Именно этот адрес записывается внутрь `.strm`-файлов. Если указать его неверно (например, оставить `127.0.0.1` на удалённом VPS), Infuse загрузит медиатеку, но не сможет запустить воспроизведение.

Значения сохраняются в `.env` (логин и пароль — в одинарных кавычках). Отдельно есть переменная `TORR_HOST` (по умолчанию `torrserver`) — внутреннее имя TorrServer в Docker-сети. При установке она не запрашивается: если нужно, добавьте строку `TORR_HOST=...` в `.env` вручную и перезапустите `install.sh` — значение используют и парсер, и Nginx-прокси, а при пересоздании `.env` строка сохраняется.

## 🍏 Подключение в Infuse

1. Infuse → **Настройки** → **Добавить файлы** → **Другое...**
2. Протокол: **WebDAV**.
3. **Адрес** — IP-адрес сервера (без `http://`), **Пользователь** и **Пароль** — из установки.
4. В разделе **Дополнительно** укажите **Порт** — значение `WEBDAV_PORT` (по умолчанию `8080`).
5. Нажмите **Сохранить** и добавьте папку в Избранное (⭐).

Infuse просканирует библиотеку, подтянет постеры и сгруппирует сериалы по сезонам. Новые раздачи появляются с задержкой до 5 минут — после очередного прохода парсера (плюс время на загрузку метаданных торрента).

## 🔄 Обновление

Обновление — это просто повторный запуск `install.sh`:

```bash
cd /opt/torrserver-infuse-bridge
sudo ./install.sh
```

Скрипт спросит подтверждение `Продолжить? [y/N]`:

- **`y`** — остановит контейнеры и обновит код (`git fetch --all && git reset --hard origin/<текущая ветка>`). ⚠️ Все локальные изменения файлов репозитория в `/opt/torrserver-infuse-bridge` будут перезаписаны (`.env`, `.htpasswd`, `nginx.conf` и данные не трогаются).
- **`N`** или Enter (по умолчанию) — код **не** обновится, но скрипт продолжит работу: предложит пересоздать `.env`, перегенерирует конфиги и перезапустит контейнеры.

Затем скрипт скачает свежие образы (`docker compose pull`) и поднимет стек. Каталоги `./ts` и `./strm_library` не затрагиваются.

Обновить только образ `parser` без переустановки (с Compose v1 — `docker-compose`):

```bash
cd /opt/torrserver-infuse-bridge
docker compose pull parser
docker compose up -d parser
```

> Образ TorrServer зафиксирован на конкретной версии (`MatriX.141`) в `docker-compose.yml` — новые версии подхватываются при обновлении репозитория, а не автоматически.

## 🛠 Администрирование

Все команды выполняются из `/opt/torrserver-infuse-bridge` (с Compose v1 пишите `docker-compose` вместо `docker compose`):

```bash
docker compose ps              # состояние контейнеров
docker logs -f strm-parser     # логи парсера
docker compose down            # остановить
docker compose up -d           # запустить
```

Основные адреса после установки (оба под Basic Auth):

- TorrServer UI: `http://HOST_IP:TORR_PORT`
- WebDAV: `http://HOST_IP:WEBDAV_PORT`

## 📁 Структура проекта

```
/opt/torrserver-infuse-bridge
├── install.sh          # установка, обновление, переконфигурация (идемпотентный)
├── .env                # параметры окружения (права 600, не в Git)
├── .htpasswd           # хэш пароля для Basic Auth (не в Git)
├── nginx.conf          # конфиг прокси перед TorrServer (генерируется)
├── docker-compose.yml  # описание контейнеров
├── strm_library/       # библиотека .strm-файлов для Infuse
└── ts/                 # данные TorrServer (конфигурация, база, кэш)
```

Скрипт `torr_to_strm.py` лежит в репозитории, но выполняется только внутри контейнера `parser` (образ собирается в CI и публикуется в GHCR).

## 🔐 Безопасность

- `.env` создаётся с правами `600`; `.env` и `.htpasswd` не попадают в Git.
- TorrServer не публикуется напрямую: внешний доступ только через Nginx-прокси с Basic Auth.
- `.strm`-файлы содержат URL с учётными данными (`http://user:password@host:port/...`), но сами доступны только через WebDAV с теми же учётными данными.

**Важно понимать:** стек работает по обычному HTTP — и Basic Auth, и учётные данные внутри URL потока передаются по сети в открытом виде. Парсер всегда записывает в `.strm` адрес вида `http://user:password@HOST_IP:TORR_PORT/...`, поэтому reverse proxy с TLS (Caddy, Traefik и т. п.) может защитить подключение к WebDAV и TorrServer UI, но **не** сами потоки — и учётные данные в них. Для доступа через интернет рекомендуется:

- ограничить доступ к портам файрволом по своим IP (ufw, Security Groups), либо
- подключаться через VPN/WireGuard — это единственный вариант, при котором шифруется и поток.

И в любом случае — использовать сложный пароль.

## 🩺 Troubleshooting

**Медиатека видна в Infuse, но видео не запускается.** Почти всегда — неверный `HOST_IP` в `.env` (адрес внутри `.strm`-файлов). Исправьте значение и перезапустите `install.sh`. Файлы перегенерируются не сразу, а при следующем проходе парсера — первый проход идёт сразу после старта контейнера, но для каждого торрента должны загрузиться метаданные (до 3 попыток с паузой 10 секунд). Если торрент не успел, его `.strm` обновится в одном из следующих проходов (раз в 5 минут). Ход обработки видно в `docker logs -f strm-parser`.

**Новая раздача не появляется в Infuse.** Проверьте логи парсера: `docker logs -f strm-parser`. Убедитесь, что контейнер `torrserver` здоров (`docker compose ps`).

**Infuse не подключается к WebDAV.** Проверьте, что порт `WEBDAV_PORT` открыт в файрволе, а логин/пароль совпадают со значениями из установки.
